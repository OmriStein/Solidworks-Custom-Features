# Adding a new feature to the Custom-Features add-in

Written against the real classes (FeatureDef / FeatureBase / FeaturePage / ParamIO), CNC Chamfer is the model to copy.

## 1. What a feature is
A SOLIDWORKS macro feature (COM class implementing ISwComFeature) plus a PropertyManager page, started from a command in the Custom-Features group (Features tab / Insert menu). There is no lower-level custom-feature API. SOLIDWORKS stores the feature's parameters and selections in the part; on every rebuild it calls the COM class's Regenerate, which returns the new body (or an error string).

One add-in (class Addin, ProgId MfgChamfer.Addin, GUID 35EB7F02-...) hosts all features; every feature has its own COM class, ProgId and GUID.

## 2. Source layout (build.bat compiles every src\**\*.cs, so new files are picked up automatically)
- src\Core: Addin.cs (host), FeatureDef.cs, FeatureBase.cs, FeaturePage.cs, ParamIO.cs (parameter write-back), Core.cs (`Core.Log` -> %TEMP%\CustomFeatures.log), ResourceIds.cs, AssemblyInfo.cs
- src\Geometry\Geo.cs: shared helpers - vector math (Add Sub Scale Dot Len Norm Cross Dist), PlaneNormal, FaceNormalAt, Ends (also for closed edges), TangentChain, IsNewFace, Cone, Prism, PrismSheared, Segment, EdgePoints, Largest, Volume, AddClipped. Use `using static MfgChamfer.Geo;` and `using static MfgChamfer.Core;`.
- src\Features\<Name>\: everything of one feature.

## 3. Checklist for a new feature "Foo"
1. Folder src\Features\Foo\ with (names are conventions; CncChamfer shows each one):
   - `FooDef : FeatureDef` - Name (command / menu title), Hint (tooltip), IconIndex (position of its icon in the toolbar_*.png strips), `Insert(sw, model)` that opens the new-feature page, optional `OnCommandPre` for Copy / Cut / Paste (return 1 = handled; most features need nothing).
   - `FooFeature : FeatureBase` with `[ComVisible(true), Guid("<NEW GUID>"), ProgId("<Namespace>.FooFeature")]`: implement `Title` (for messages), `Build(sw, feat)` (the rebuild: read parameters and selections from `feat.GetDefinition()`, work on the edit body (`data.EditBodies`), return the new IBody2, or throw - the message becomes the feature's rebuild error) and `ShowPage(sw, model, feat, data)` (Edit definition: `new FooPage(...).Show()`). Never reuse a GUID / ProgId, and never rename these classes once released: the registry stores the type name and existing parts store the ProgId.
   - `FooPage : FeaturePage` - the PropertyManager page. Call `CreatePage(sw, FooDef.Title, hint)` first, add group boxes / controls, add every group box, label and bitmap button to `keep` (or use the `Number(...)` helper, which does it), override only the handlers you use (OnClose, AfterClose, OnNumberboxChanged, ...), set `Addin.PageOpen = true` before `page.Show2(0)` and false in AfterClose (the enable callbacks must stay trivial while a page is open).
   - Params class (like ChamferParams): see section 4.
   - Inserter (like Chamfer's): `InsertMacroFeature3(name, ProgId, null, Names, Types, Values, null, null, new[]{ new DispatchWrapper(editBody) }, FeatureBase.Icons("<prefix>"), swMacroFeatureByDefault)` after selecting the input entities with a mark; report a rebuild error with `f.GetErrorCode2`.
   - Engine code (the geometry).
2. Register it: add `new FooDef()` to `Addin.Features` in src\Core\Addin.cs. The command group, toolbar, Features-tab box, Copy/Paste hook and the registration text are built from that list. Limit today: callbacks are by method name (OnInsert0..OnInsert3), so more than 4 features means adding OnInsertN methods.
3. Icons (generated by icons.py into icons\, embedded into the DLL by build.bat as resources "icons.<file>" and extracted to %LOCALAPPDATA%\CustomFeatures\icons at run time by `Addin.Icon(name)`):
   - feature tree: `<prefix>_reg_20|32|40.png`, `<prefix>_sup_...` (suppressed), `<prefix>_hl_...` (highlighted) - CNC Chamfer uses prefix "feat"; pass your prefix to `FeatureBase.Icons(prefix)`. Extend icons.py to write them in the same style (SolidWorks-like isometric block, yellow cut, blue tool).
   - command icon: one more image in the toolbar_20|32|40|64|96|128.png strips (one image per feature, in IconIndex order; today they hold the chamfer, copy and paste variants).
   - pm_title.png is shared by all pages.
4. Build and register: `build.bat` (SOLIDWORKS closed), `install.bat` registers out\CustomFeatures.dll with RegAsm /codebase (admin). RegAsm registers every ComVisible class, so the new COM class is registered automatically. The DLL loads inside the SOLIDWORKS process: restart SOLIDWORKS after every build.
5. Test with the harness (section 5), then by hand: command on the Features tab, page, OK, edit definition, rebuild after changing an earlier feature, delete / undo.
6. README line, version in src\Core\AssemblyInfo.cs, commit, release zip = out\CustomFeatures.dll + install.bat + uninstall.bat + README.md (no interop DLLs, no icons folder).

## 4. Parameters
Each feature has its own params class with plain fields and parallel arrays `Names`, `Types` (swMacroFeatureParamType_e: Double / Integer / String; booleans are stored as the strings "1" / "0") and `Values()` (strings, doubles formatted with "R" and the invariant culture), exactly what `InsertMacroFeature3` takes. Edit definition writes them back with `ParamIO.Write(data, Names, Types, Values())`, which redefines the whole set when a stored feature lacks a name (feature made by an older version) and then sets every value by name, so a new parameter can simply be appended to the arrays. `Read(data)` stays in the params class: a missing or invalid parameter in an old feature must read as its default (ChamferParams.Read shows it).
SOLIDWORKS only keeps what is stored through InsertMacroFeature3 / ModifyDefinition, so geometry that must survive (edge end points) is stored as encoded strings and matched on edit (see ChamferParams.Edges and the missing-edge logic in ChamferPage). Never rename or reorder stored parameter names of a released feature.

## 5. Test harness (the author's PC, not in the repo)
- %TEMP%\H.cs + %TEMP%\cfrun.ps1 compile with Add-Type against out\CFTest.dll (`build.bat CFTest`: same source with the SolidWorks interop referenced instead of embedded, because C# cannot call embedded-interop generics across assemblies) and the interop DLLs in SOLIDWORKS\api\redist. It attaches to the running SOLIDWORKS (Marshal.GetActiveObject, typed C# - PowerShell late binding fails), runs `Inserter.Insert` for chosen edge indices, prints volumes and deletes the feature again.
- Important: inserting a feature makes SOLIDWORKS regenerate it with the add-in DLL loaded in the SOLIDWORKS process, not with CFTest.dll. After a code change run `build.bat` (SOLIDWORKS closed) and restart SOLIDWORKS before testing.
- Commands: List (edge indices - re-list after features change), Many -Spec "pick(+ separated),angleDeg,sizeMm,toolMm,clrMm;...", Cmp, Chk, Prev, BlAll, Stages, Del (also deletes every feature after it), RollTo... Env CF_TIP (mm) sets the tip offset. Typical test: base volume, insert, volume after, compare with the recorded numbers.
- The harness does not exercise the PropertyManager page, Edit definition or Copy/Paste - check those by hand.
- Test parts are in test\ (BlendDemo, StepBlock, InsideCorner, ArcWall, ...).

## 6. Pitfalls already paid for
- Keep every PMP control, group box and bitmap button referenced from managed code (`keep`); otherwise the GC finalizes the COM wrapper and SOLIDWORKS stops all page callbacks or the control vanishes.
- Do not read PMP controls in OnClose; do not call the SW API from timers (use OnIdleNotify); Selectionbox.CurrentSelection is crash-prone (only from direct user clicks).
- COM arrays to SW: DispatchWrapper[]. Regenerate returning a string = rebuild error.
- Re-creating a command group in the same ConnectToSW gives command ID 0; command IDs can collide with SOLIDWORKS resource strings (command search shows a wrong label): the spacer group (HKCU\Software\MfgChamfer\SpacerCount) handles it.
- Macro-feature parents cannot be overridden; children get no DeleteItemPreNotify; lost selections are dropped silently - store geometry and match by end points / line.
- Closed circular edges have no vertices - use Geo.Ends.
- Work on the edit body itself in Build (copying it drops face identities); only new faces get user IDs (see Engine.Build).
- Expected-volume check (removed <= Expected*1.002) catches wrong cuts; boolean cut order matters with overlapping tools.
- C# `Environment` is ambiguous with SolidWorks.Interop.sldworks.Environment: write System.Environment. The harness class H has a method Geo(): write MfgChamfer.Geo.X in H.cs.
- SW started via COM (-Embedding) does not load add-ins; launch SLDWORKS.exe by full path. Moving / renaming the DLL needs RegAsm /codebase again.
- Prefer native-looking, native-behaving solutions over clever workarounds.
